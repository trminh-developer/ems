BÁO CÁO PHÂN TÍCH MÃ NGUỒN (SOURCE CODE)

DỰ ÁN: ỨNG DỤNG HẸN HÒ (HEARTCONNECT)

1. Tổng quan Kiến trúc Hệ thống (Architecture)

Dự án được xây dựng theo mô hình Client-Server (SPA - Single Page Application):

  • Frontend: React, TypeScript, Vite, Bootstrap 5. Quản lý trạng thái bằng React Hooks (useState, useEffect, Context API). Giao tiếp API qua Axios.
  • Backend: Node.js, Express.js, TypeScript.
  • Cơ sở dữ liệu (Database): MySQL, quản lý thông qua ORM Sequelize.

2. Cấu trúc thư mục (Directory Structure)

Hệ thống chia làm hai phần độc lập hoàn toàn (Microservices-like):

  • /frontend/src/: Chứa các Component, View (giao diện), Hook (logic UI), Model (kiểu dữ liệu) và Service (gọi API).
  • /backend/src/: Chứa các Controller (xử lý logic), Model (định nghĩa DB), Route (định tuyến API) và Config.

3. Phân tích Cơ sở dữ liệu (Database Models)

Toàn bộ DB được định nghĩa tại backend/src/models/index.ts.

Bảng User (Người dùng)

  const User = sequelize.define('User', {
    id: { type: DataTypes.UUID, primaryKey: true },
    email: { type: DataTypes.STRING, unique: true },
    password: { type: DataTypes.STRING }, // Mật khẩu đã mã hóa (hashed)
    role: { type: DataTypes.ENUM('ADMIN', 'CENSOR', 'USER') } // Phân quyền
  });

Giải thích: Định nghĩa khung dữ liệu của người dùng. Mỗi user có một ID duy nhất dạng UUID để bảo mật. role sử dụng kiểu ENUM để giới hạn quyền hạn chỉ nằm trong 3 mức.

Các bảng liên kết (Associations)

  User.hasMany(VerificationRequest, { foreignKey: 'user_id' });
  VerificationRequest.belongsTo(User, { foreignKey: 'user_id' });

Giải thích: Quan hệ 1-N (Một người dùng có thể gửi nhiều yêu cầu xác thực). Khóa ngoại user_id dùng để liên kết bảng.

4. Phân tích chi tiết Logic Backend (Controllers)

4.1. Module Xác thực (Authentication)

File: AuthController.ts

  // Kiểm tra email tồn tại
  const user = await User.findOne({ where: { email } });
  if (!user) return res.status(401).json({ error: 'Invalid credentials' });
  
  // So sánh mật khẩu bằng bcrypt
  const isValid = await bcrypt.compare(password, user.password);
  
  // Tạo JWT Token
  const token = jwt.sign({ id: user.id, role: user.role }, JWT_SECRET, { expiresIn: '24h' });

Giải thích từng dòng:

  • Dòng 1-2: Truy vấn cơ sở dữ liệu tìm user theo email. Nếu không thấy, trả về lỗi 401 (Unauthorized).
  • Dòng 4: Dùng thuật toán Bcrypt để so sánh mật khẩu người dùng nhập vào với mã băm trong DB. Đảm bảo an toàn tuyệt đối, không lưu mật khẩu dạng plaintext.
  • Dòng 7: Nếu hợp lệ, cấp phát một JSON Web Token (JWT) chứa thông tin ID và Quyền (role), có thời hạn 24 giờ. Token này được gửi về Frontend để xác thực các request sau này.

4.2. Module Quản trị viên (Admin Controller)

File: AdminController.ts

  export const updateUserRole = async (req: Request, res: Response) => {
    try {
      const { id } = req.params; // Lấy ID của user từ URL
      const { role } = req.body; // Lấy chức danh mới từ dữ liệu gửi lên
      
      const validRoles = ['ADMIN', 'CENSOR', 'USER'];
      if (!validRoles.includes(role)) return res.status(400).json({ error: 'Invalid role' });
      
      const user = await User.findByPk(id); // Tìm user theo khóa chính
      
      user.role = role; // Gán quyền mới
      await user.save(); // Lưu lại vào DB
      
      return res.json({ message: 'Thành công', user });
    } catch (error) { return res.status(500).json({ error: error.message }); }
  };

Giải thích từng dòng:

  • Dòng 2-4: Giải nén tham số từ Request (URL params và body).
  • Dòng 6-7: Kiểm tra tính hợp lệ của Role. Nếu truyền lên chức danh bậy bạ (ví dụ: 'HACKER'), hệ thống chặn ngay bằng lỗi 400 (Bad Request).
  • Dòng 9-12: Gọi lệnh cập nhật vào Database thông qua Sequelize (ORM). Lệnh save() sẽ sinh ra câu lệnh UPDATE SQL tương ứng dưới nền.

5. Phân tích chi tiết Logic Frontend (React)

5.1. File cấu hình API (apiClient.ts)

  apiClient.interceptors.request.use(config => {
    const token = localStorage.getItem('token');
    if (token) config.headers.Authorization = "Bearer " + token;
    return config;
  });

Giải thích: Interceptor này tự động đính kèm JWT Token vào Header của MỌI request gửi lên server. Frontend không cần phải code thủ công ở từng chức năng.

5.2. File Giao diện Admin Users (AdminUsersView.tsx)

  const [users, setUsers] = useState<User[]>([]); // State lưu danh sách
  
  // Hàm chạy 1 lần khi load trang
  useEffect(() => {
    fetchUsers();
  }, []);
  
  // Hàm cập nhật quyền
  const changeUserRole = async (id: string, newRole: string) => {
    if (!window.confirm('Bạn có chắc muốn cấp quyền?')) return;
    await apiClient.put("/admin/users/" + id + "/role", { role: newRole });
    // Cập nhật lại State UI ngay lập tức mà không cần F5
    setUsers(users.map(u => u.id === id ? { ...u, role: newRole } : u));
  };

Giải thích từng dòng:

  • Dòng 1: Khai báo State users bằng React Hook. Khi State này thay đổi, toàn bộ bảng UI sẽ tự động render lại.
  • Dòng 4-6: useEffect với mảng phụ thuộc rỗng [] đóng vai trò như sự kiện onLoad. Tự động gọi API lấy danh sách ngay khi vào trang.
  • Dòng 11: Gọi API bằng phương thức PUT để thay đổi quyền trong DB.
  • Dòng 13: Đây là kỹ thuật Optimistic UI Update. Thay vì phải tải lại cả danh sách (tốn thời gian), ta dùng hàm map để tìm đúng user vừa đổi và cập nhật Role ngay trong RAM trình duyệt, giúp UI phản hồi mượt mà ngay lập tức.

6. Kết luận

Hệ thống tuân thủ chặt chẽ kiến trúc RESTful API, phân chia rõ ràng trách nhiệm giữa Frontend và Backend, bảo mật bằng JWT và bảo vệ toàn vẹn dữ liệu bằng ORM. Mã nguồn được cấu trúc module hóa (theo tư tưởng Clean Architecture), dễ bảo trì và mở rộng trong tương lai.
